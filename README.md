# PrecarityScan (v2): measuring precarious gig work with data science

A full data-science project for gig workers (delivery, ride-hailing, home services): data collection template, cleaning
pipeline, statistical analysis, a transparent **Precarity Index**, ML prediction of **financial stress**, worker segmentation,
time-series analysis, fairness audit, an interactive **Streamlit** app and a **FastAPI** scoring service with model versioning
and drift monitoring.

> **Data status:** no real worker data is included. `data/sample_data.csv` is **synthetic** (see `docs/DATA_CARD.md`).
> Collect real data with `docs/SURVEY_FORM.md` before drawing real-world conclusions.

## Quick start
```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python scripts/bootstrap.py       # data -> full analysis + model -> demo accounts (passwords printed once)
streamlit run app.py              # dashboard
uvicorn api.main:app --reload     # API docs at http://127.0.0.1:8000/docs
python -m unittest discover -s tests    # or: pytest tests
```

## Typical workflow
1. `python scripts/generate_data.py` (or put your cleaned survey CSV at `data/sample_data.csv`).
2. `python scripts/run_analysis.py` writes every table and figure for the report (`--no-tune` is faster).
3. `python scripts/train.py` registers a new model version; `python scripts/retrain.py --new new_rows.csv` retrains and promotes only if hold-out AUC is not worse than the live model by more than 0.01.
4. `python scripts/monitor.py --current new_rows.csv` prints PSI drift per feature.
5. Accounts: `python scripts/create_user.py <name> <worker|researcher|admin>`.

## Snapshot of results on the synthetic data (regenerate with run_analysis.py)
See `reports/results.md`. Highlights: best model by CV is regularised logistic regression (CV ROC-AUC about 0.71; hold-out about 0.74);
tree ensembles overfit (train AUC about 1.0). Strongest predictors: dependents, income volatility, income, savings.
Precarity-index risk bands are sensitive to weights (see sensitivity analysis), so treat bands as indicative.
